# 从演示到真实模型的验收步骤

## 1. 先跑离线流程

在项目目录执行 `mvn package`，然后运行 `scripts/demo.ps1`。脚本创建一个只含 `Hello.java` 的临时示例仓库，默认启用 `--demo`。

输入 `/new A` 和 `/new B`。观察两个不同任务 ID，直到 `/tasks` 显示 `READY`。用 `/show` 找到两个副本目录，检查同名 `demo-result.txt` 各自包含 A 和 B；源示例仓库没有这个文件。

输入 `/new [ask] 问题演示`，等待它进入 `WAITING_INPUT`。此时再创建普通任务，确认后者可以完成。然后用 `/follow <前一个任务ID> 我的答案` 回答，检查它继续完成。

## 2. 检查审批

输入 `/new [command] 命令演示`。终端展示审批 ID、完整命令 `echo superagent-demo` 和工作目录。

先 `/deny <审批ID>`，通过 `/show` 检查没有任何实际命令执行记录。再创建另一个相同任务，这次 `/approve <新审批ID>`，检查实际退出码和日志路径。

不能把“模型说命令成功”当成证据，必须看命令工具记录。

## 3. 检查重启

在一个任务等待审批时 `/exit`。重新运行演示脚本，原任务应为 `INTERRUPTED`。旧审批 ID 不再可用。

`/resume <任务ID>` 后生成新审批。检查完整命令，再决定批准或拒绝。恢复保留原目录和会话，不是创建一个新任务从头开始。

真正的“执行一半进程消失”由 `RecoveryTest` 的子 JVM 测试覆盖：命令已经写出 marker 文件，但其结果未进数据库。新进程启动后必须保留文件且不能重复执行该命令。

## 4. 检查补丁

待任务 `READY` 后 `/diff <任务ID>`。打开输出的 `changes.patch`，应包含新增的 `demo-result.txt`。源仓库保持原样。`/accept` 只标记验收，不会自动应用补丁。

## 5. 再切真实模型

根据 README 设置模型环境变量，用 `scripts/demo.ps1 -Real` 启动真实模式。该参数会使用独立的 `target/real-state`，不会把离线模型的会话发送给真实模型。

建议第一条需求保持很小：

```text
/new 阅读 Hello.java，把输出改成 Hello, Super-agent!。修改前先读文件，提出 javac Hello.java 和 java Hello 的验证命令，等我批准。
```

检查读取、修改、审批和命令日志，再检查补丁。若模型询问信息，用 `/follow` 回答。若 API 配置不正确，任务进入 `FAILED` 并保留现场；修正环境变量需要重启进程，再 `/resume`。

真实模型可能选择不同的工具顺序或实现方式，因此按最终文件与实际验证记录验收，不按它是否复述了某段固定文字来判断。

首版没有做真实 API 调用验收，不预先声称特定任务成功率或 Token 成本。
