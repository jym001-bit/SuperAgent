### 环境注意

`mvn test` 需要完整的进程与命名管道能力。在受限沙箱里 `git clone` 会以 `sh.exe: couldn't create signal pipe, Win32 error 5` 失败，表现为大量「15 秒未达条件」的假失败；放宽沙箱后同一份代码 90 个测试全绿。因此 CI 只在 `ubuntu-latest` 上跑（见 [CI 门禁](ci.md)）。

### 这一阶段仍未验证

- **Docker 容器链路**：本机未安装 Docker。只交付了镜像与 compose 定义、静态复核和部署验收清单，没有构建或运行过镜像。
- **真实 GitHub 端到端**：仍是本地 HTTP 与远端故障替身。
- **真实模型评测数字**：已完成两次真实运行（2026-11-08，`deepseek-flash`）。第 1 次 6/9，其中 2 个失败是传输层（`ConnectException`）——这促成了模型重试与诊断的修复；第 2 次 8/9（88.9%），传输层失败为 0，证明重试生效。唯一残留失败是 `ambiguous-refusal`：模型自建基准并作出正确的性能优化，但没有先澄清验收标准。据此收敛了 Worker 的「无验收标准先澄清」策略，该策略尚未经真实运行验证。详细拆解见 [评测手册](eval.md#真实模型基线2026-11-08)。
- **真实模型结果的稳定性**：只有两次运行，尚没有多次运行的中位数，不能据此声称长期成功率。
